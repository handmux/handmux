# 修复 Claude 对话入口丢失 · 长时间运行不再变卡

## English

**Fixes lost Claude chat entries on WSL2, and unbounded internal state after long runs.**

### Fixed

- 🧩 **Claude chat entries no longer vanish on WSL2.** Process identity no longer follows the system clock, so a clock adjustment can no longer make one live Claude process look like a new one (issue #6).
- 📊 **Claude activity shows up again on Linux** (working / idle / waiting).
- 🔄 **Claude stays recognized after its own auto-update** removed the older binary file.
- 🧹 **Internal state is reclaimed.** Runs that can never be consumed again, and Hook sources that never get acknowledged, are now bounded — long-running servers stop slowing down and stop growing on disk.
- 💬 **No more misleading "Could not connect to the Codex session"** flash while a conversation switches; it shows the shared loading state instead.

## 中文

**修复 WSL2 上 Claude 对话入口丢失，以及长时间运行后内部状态无限增长的问题。**

### Fixed

- 🧩 **WSL2 上 Claude 对话入口不再反复消失。** 进程识别不再跟随系统时间，时钟调整不会再把同一个 Claude 进程误判成新进程（issue #6）。
- 📊 **Linux 上恢复显示 Claude 的活动状态**（进行中 / 空闲 / 等待）。
- 🔄 **Claude 自动更新删掉旧版本文件后仍能识别。**
- 🧹 **内部状态会回收。** 不再可达的会话通道、以及一直没被确认的 Hook 源文件都有上限，长时间运行不再变卡、不再持续占磁盘。
- 💬 **切换会话时不再闪现「无法连接 Codex 会话」**，过渡期间显示统一的加载状态。
